# 跨任务工作规则

这些约束适用于所有功能；局部任务仍需读取对应专题文档。

## 依赖与运行时

- 遵循 [architecture.md](../architecture.md) 的依赖方向。领域层不依赖 UI、GPU 或操作系统。
- CLI 与 Slint 使用同一 application/session 服务，不在入口层复制业务编排。
- 新运行时路径不引入 Python、C++、CUDA 或直接 Vulkan 依赖。
- 初始迁移阶段避免 `unsafe`；性能优化需要 benchmark 或 profile 依据。

## 兼容与失败语义

- C++ 仓库只作为行为参考，不作为本仓库依赖，也不在本仓库修改。
- 兼容读取器、旧 fixture 和迁移路径在确认替代方案前保留。
- 部分失败、取消、重试、检查点和导出都必须有明确且可测试的语义。
- 检查点和导出使用临时文件加原子替换；恢复只能从完整检查点开始，并报告失败原因。

## 变更边界

- 先架构后功能，不绕过依赖边界直接接入实现。
- 提交前按功能文档执行适用的完整检查，并保证干净 checkout 可复现。
- 每个功能点使用独立 Git worktree；开发、测试、文档同步和 diff 检查完成后才能提交并合并。
